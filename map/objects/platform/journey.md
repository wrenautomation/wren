# journey

One person on one node of the shape (schema `pipeline`, table `journeys`), with the trail of edges they crossed and a `deals` row once they reach an offer node. A person has one open journey; one who left a journey (done or dropped) and enters again, say by leaving a group and coming back, opens a new journey and the old one stays closed. Built: schema, the spine steps, the version carry, manual moves, records, console, numbers and the merge.

## Why this shape

The row is a cache. The truth is spine events with subject `journey:<id>`, so a transition, its event and its person share one workspace DB and one transaction. A shape version carries open journeys forward on the same node; a journey whose node a later version removed stays on its old version (the ghost) and moves by that version's edges ([[platform/shape]]).

One open journey per person, not per funnel: one shape per database, and an upsell is the same journey going deeper. The advisory lock `journey:<profile>` (`lockPerson`) is the guard; the unique index `uq_journeys_open` (`profile_id` where open, migration 0307) is the backstop that makes a second open row an error.

## Shape

- `journeys` (`schema.ts:154`): `profile_id` FK `profiles.id`; `version` FK `shape_versions`, not null; `node` (a node id of that version), not null; `trail` jsonb, a list of `Crossing` `{ edge, from, to, at }` (`model.ts:130`); `status` open|done|dropped; `entry` (the source node id that opened it, `manual` when none claims it) and `entry_ref` (the cause); `owner` text, null = nobody (migration 0308): the team member who works it, an email as a person on the team is named elsewhere (`created_by`); `legacy_deal` uuid (old Opportunities id, unique where set). Migration 0308 added `owner` and backfilled it once from the newest manual arrival's email (`cause.ref`) in `events`; it has no index, since `mine` filters the rows in memory. Migration 0307 dropped the legacy `funnel`, funnel `version` and `stage` and renamed `shape_version` to `version`; its guard raises first when a journey has no node or version, or a person holds two open journeys.
- `deals` (`schema.ts:201`, TS export `pipelineDeals`): `journey`, `node` (the offer node it was made at; null on a deal made before the shape; unique `uq_deals_journey_node`), `terms_version` null until signed terms are known, `collected_cents` a fold of payment events. A journey holds one deal per offer node: migration 0307 dropped `uq_deals_journey` (one deal per journey). A save with `moves` sends open deals to the new node ([[platform/shape]], `remapDeals`).
- `pathOf(body, from, to, { loops? })` (`model.ts:404`): replaces `nextStage`. Automatic moves take the shortest flow path: every edge on it is a crossing, the nodes between are skipped (`passedThrough`). Nothing moves backward; a node on the trail is never entered twice.
- `journey.move` (`steps.ts:152`, `journeySteps`): a cause event reaches `m_<node>`. It finds the person (`personOf`, `journeys.ts:55`). With no open journey it opens one on the newest version, only when `opensAt` (`entry.ts:67`) lets the cause in: a manual open or a composed shape (journey port) at any node a live source feeds; else a source whose `via` and `channel` match, or the group or sourced source the cause names (`entryOf`, `entry.ts:91`, picks the source); the first crossing is the source's edge. Where the cause came from is its explicit facts (`factsOf`), else what a form's payload says (see Attribution below); `entry_ref` keeps them (`channel`, `platform`, `campaign`, `adCampaign`, `first`). With an open journey on this version it crosses the path to the target (a move back or a repeat is refused; a forced move with a reason crosses no edge). A cause with a `loop` crosses a loop edge: it closes the old journey (dropped, reason `loop <edge>`) and opens a new one at the loop's end with the old entry. One `atomic` transaction. Emits `moved` with subject `journey:<id>` and `{journey, profile, version, from, to, edges, skipped, loop?, forced?, cause}`.
- `journey.stage` (`steps.ts:324`): the arrival at `s_<node>`. Writes a `profile_events` row (kind `journey`); sets `done` at a node no flow edge leaves (`isEnd`); makes the `deals` row at an `offer` node (newest `offer_versions` number; none, no deal and a warning); signs the deal under the plan's live terms at a `plan` node (`signDeal`); runs the node's research; and fires `trigger.journey` (`entered`, one `skipped` per skipped node, `dropped`). The fires go through `StepAt.fire`, sent after the step result is kept ([[platform/spine]]). The facts are `{trigger, node, change, sale?}`; `sale: true` marks entering an offer node (`told`, `steps.ts:443`). `webhookEventsOfFired` (`webhook-events.ts:38`) turns an entered or dropped fire into `journey.moved`, and a `sale` one into `deal.won` as well ([[platform/webhook-subscription]]). The `journey.moved` data has `node` and, for one more release, `stage` with the same id.
- `dropJourney` (`journeys.ts:165`): set `dropped`, return the event for `in.dropped` of the newest version. The `Journeys` service calls it and emits.
- `Journeys` service (`restate.ts:82`, bound in `apps/worker/src/services.ts`): `open`, `move`, `drop`, `assign`, `rebuild`; `client` null is Wren's workspace. `openEmit` (`moves.ts:78`, `{person, at?, entry?, by}`; `at` defaults to the first node a live source feeds) and `moveEmit` (`moves.ts:123`, `{journey, to, by, reason?}`) build a spine event with cause `manual` (operator in `cause.ref`) for `in.<node>` of the shape workflow; the workflow's own `journey.move` step writes the row, so there is no second write path. A manual open uses subject `manual:<uuid>`, so a repeat after a drop is a new arrival. The `journey.move` step sets `owner` on a manual open to the opener when the opener's `cause.ref` is an email (`ownerOf`, `journeys.ts:30`; an agent or a shell name leaves it null), and a loop's new journey keeps the old owner. `assignJourney` (`moves.ts:211`, `{client?, journey, to}`) sets or clears it (`to` null): `to` must be an operator, or a member of `client`; any other value is refused. A closed journey may be assigned. It writes the column only, no history row; `Journeys/assign` and the console `journeysAssign` call it. `rebuildJourney` (`moves.ts:258`) recomputes version, node, trail and status from the `journey:<id>` arrivals. `idOf` refuses a bad id before the database does.
- Records (`records.ts`): `pipeline.journey` (`journeyRows`, `:380`; open, mine, stale, ghost, done, dropped, all; fields id, name, profile, email, version, node, node_name, trail, status, flag, ghost, entry, owner, days_at_node, reason, opened_at, moved_at, closed_at), `pipeline.deal` (`dealRows`, `:524`; open, won, lost, all; schedule from `scheduleOf`), `pipeline.entry` (`entryRows`, `:616`; one row per source node of the newest shape: via, channel, campaign, parked, open and all journeys, last arrival), `pipeline.shape` ([[platform/shape]]), `pipeline.terms` and `pipeline.offer` ([[platform/offer]]). `trailOf` (`:364`) reads one journey's trail with its edge ids and names. `mine` is the open journeys whose `owner` is the viewer (field `owner`, an actor). The type opts into custom fields (`custom: { owner: null, exists }`; the console sets `owner` to the client in a client workspace and runs `withCustomFields` on it), so a workspace's own fields show as `x_<key>` columns; the pipeline console has no record edit, so a value is set by the Set field node ([[platform/custom-field]]). Stale is a node's `idleDays` at that node, else 14 days (`STALE_DAYS`). A ghost is an open journey on an older version whose node the newest shape lacks. Journey rows carry hidden `profile` and `email` so Today's Move list can group a person's other moves under their journey.
- Numbers (`views.ts`, migrations `0300_pipeline_numbers`, `0306_shape`): views `node_counts`, `edge_flow`, `source_numbers` over `events` with workflow `shape.v%`; the old `stage_counts`, `stage_flow`, `entry_numbers` stay one release as views over them. `numbers.ts` reads them and builds the `pipeline.number` rows of kind `node | edge | offer` (`NumberKind`): per node people now, arrived, skipped, left, median days; per edge crossings; per offer money and deals. A version carry (cause `version`) is no arrival.
- Node research (`research.ts`, `requestResearch`): `journey.stage` on a non-dropped arrival at a step or offer node whose `research` is `light` or `full` claims one `journey_research` row per `(journey, node)` (`schema.ts:257`; the `stage` column holds the node id) and asks once, against the newest `offer_versions.body.icp` of the nearest offer at or below the node (`offerFor`, `icpOf`; context only, nothing scores fit). `light`: the injected `Researcher.light` reads the workspace's own rows in the claim's transaction (role, firm, address verdicts) into `result`; state `read`. `full`: state `queued`, then `Researcher.full` queues and sends the person-research run without waiting; state `started` with `lookup_id`, or `skipped` with a note. A start that fails leaves `queued`, and the next repeat of the step starts it. A repeat that finds the row asks nothing. The ask never stops the arrival: a throw is logged. The worker's `journeyResearcher` (`apps/worker/src/journey-research.ts:21`) wires `readProfileFacts` + `latest_verifications` for `light` and `queueProfileResearch` + `ProfileResearch/<profile>/run` for `full`; a client workspace's `full` is skipped (person research is Wren's own People only). One `profile_events` line (kind `journey`) per ask.
- `sourced` cause: kind `sourced`, ref the list id, `entry_ref` carries `source` and `row` (the `people.id`). `sourcedPass` (`sourced.ts:45`) is the tail: for each list a live, unparked `sourced` source of the newest shape names, it reads the `people` rows of that import batch past a cursor, maps each to its profile by the `person` key, and returns `trigger.source` fires. The worker's `SourcedFeed/all` loop (`apps/worker/src/sourced-feed.ts:43`) keeps the cursors per workspace and list and sends the fires with `spineFire`. Members without a profile are skipped and counted.
- Attribution (`attribution.ts`): a lander form reaches the spine through its door with the whole payload as event data: the page's `utm_*`, `r`, `ref`, and the visitor's `first_touch` and `last_touch`. `touchFacts` (`attribution.ts:23`) reads a touch with `touchChannel` (`@wren/core/clients`, the Search app's reading) as `CauseFacts` `{channel, platform, campaign}`: a paid touch (`utm_medium` paid or cpc) is channel `ads`, platform the lowercased `utm_source` (`meta`), campaign the lowercased `utm_campaign`. `attributionOf` (`:44`) returns the page's facts (else the last touch's) as the cause and the first touch as `first`. In the open path of `journey.move`, `withAdCampaign` (`:69`) adds `adCampaign`, the `ad_days.campaign_id` the word names (by id, by campaign name, or by the name as a `/go/` word, newest day first), so an ads source whose `campaign` is Meta's id matches and `source_numbers` cost (`ad_days.campaign_id = source.campaign`) joins. `matches` (`entry.ts:31`) compares a source's `channel` with the cause's channel or platform, and its `campaign` with the word or `adCampaign`. The visitor's first touch (when the payload has one) replaces the rollup's `first_channel` as the first-touch fallback; that rollup holds an event channel (`site`, `email`), never a campaign, so it cannot match an ads source. Gaps: the campaign on a touch is the `utm_campaign` word, a name and not Meta's id, unless the ad's url tags say `{{campaign.id}}`; the Meta audit recommends `{{campaign.name}}`. Only events with a touch payload carry a campaign: a booking or a reply arrives without one and matches on its channel. Meta lead forms are not read into People, so they open no ads journey.
- `carryJourneys` (`carry.ts:32`): open journeys of an older version move to the new one at the same node, with an arrival at `shape.v<to>` node `s_<node>` and cause `{kind: "version", ref: <old>}`. A node the new body lacks keeps the journey on its old version unless the save names a `moves` target. `saveShape` calls it, then `remapDeals`, in its own transaction ([[platform/shape]]).
- `spine_executions` titles a `journey:<uuid>` subject "Name: node" (migration `0307_journeys_guard` recreated the view on `node` alone).
- `journey_research` (migration `0301_journey_research`): not audited; a cache of what was asked.
- Migration `0295_pipeline`. The six first `pipeline` tables are audited, area `money` (`packages/db/src/audit/install.ts`).
- Board (`apps/portal/web/src/modules/deals/board.tsx`; module id `pipelines`, nav "Pipelines" at Wren, "Journeys" at a client): reads `pipeline.shape` (`recordsGet` detail: body and depths) and `pipeline.journey` (open, plus the 20 newest done). A lane per non-source node, by depth then name; offer nodes are tone good; a card per journey. A journey on a node the newest version lacks (ghost) sits in its own "(older version)" lane and can only be dropped. A move checks `pathOf` (`@wren/pipeline/model`, no revisits) on the client, then calls `pipeline/journeysMove`; a drop with a reason calls `pipeline/journeysDrop`; both go through `ACTIONS.run`, and the server decides. The Funnels page is gone; the shape page is Business Map phase M2. Lanes and drag come from the shared `apps/portal/web/src/kanban.tsx` that the Notes board uses ([[platform/boards]]).
- Causes. A touch moves a journey through `trigger.touch` (the `TouchFeed` loop). Payments reach `pipeline.collect` (`packages/pipeline/src/collect.ts`, in workflow `pipeline.money`, heard in every workspace): paid adds, refunded subtracts `deals.collected_cents` (floor 0) for the deal named in `data.deal`, else the person's newest open deal (for `data.offer` when given). Once per payment change: a `profile_events` line (source `collected`, id the subject's hash) is the claim, in the same transaction.
- Merge (`mergeProfiles`, `packages/core/src/profile-pipeline.ts:21`): `journeys.profile_id` and `deals.profile_id` move to the kept profile under the `journey:<profile>` advisory locks (id order). Two open journeys: the deeper node (`shape_versions.depths` of the journey's version; a tie keeps the kept profile's) stays open, the other is `dropped` with reason `merged`. No `journey` event is sent for that drop.
