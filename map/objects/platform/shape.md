# shape

The map of one business: a directed graph of sources, steps, offers and plans that people walk down to money (Business Map; replaces the ordered funnel). One shape per database. A version is a row of `shape_versions`, append only.

## Why this shape

An upsell or a second route into one offer is a node and an edge, not a second list. Nothing above it changes. Depth (the longest flow path from a source) gives code the order it used to read from stage position.

A node id is the spine node id, so it never goes, moves or gets renamed: versions only add and remove. A journey never arrives twice at one node in one version (`events` is unique per workflow, node and subject), so a way back is a `loop` edge: it closes the journey and opens a new one at the loop's end. Nobody sits on a source: an opening crosses the source's edge and lands on its target.

The file form (YAML) is the way to read, diff in git and write a whole version at once. The database stays the source of truth.

History works like git, without a git server in the loop. A **draft** is a body saved beside the live shape; an agent or a person writes it, proposes it, and a person applies it as the next version or drops it with a reason. **Blame** reads one node's or edge's lines from the versions. **Undo** reverses one line of a past diff on the newest body. A **tag** names a version and never moves. The **mirror** copies each version as one commit of `shapes/<workspace>.yaml` to a private GitHub repo (`wrenautomation/sops` by default), so `git log` and `git blame` read the shape's history. The mirror is a copy that catches up: a save never waits for it and never fails because of it, and the next run commits what is missing, oldest first. A draft is a row, not a git branch.

## Shape

- `ShapeBody` (`model.ts:123`): `name`, `nodes`, `edges`. Node kinds: `source` (`via` organic, outbound, ads, referral, sourced, group, manual; `channel`, `campaign`, `source`, `group`, `parked`; an ads source's `campaign` is Meta's campaign id, which also joins its cost in `source_numbers`, or a `/go/` word: [[platform/journey]] "Attribution"), `step` (`action`, `advance` list of `Advance`, `idleDays`, `research`), `offer` (`offer`: the registry offer id; reaching it makes the deal), `plan` (`terms`: the plan slug of the offer above it; reaching it signs the deal under live terms). Edge kinds: `flow` (down, toward money; the flow graph is acyclic) and `loop` (back up; left out of layers). The id `dropped` is reserved (`DROPPED`). An edge id defaults to `<from>_to_<to>` (`edgeIdOf`, `model.ts:164`).
- `checkShape(next, ctx)` (`model.ts:184`): pure; returns plain-English errors. Ids valid and unique; at least one source; known triggers; no cycle in flow edges; a `group` source names an active segment (`ctx.group`); a `sourced` source names an `import:<id>` that exists (`ctx.source`). The caller passes the trigger set (`TRIGGER_IDS` in core `logic.ts`), so the file imports no spine.
- `depthOf(body)` (`model.ts:373`): longest flow path from any source; loops ignored; safe on an unchecked body. `pathOf(body, from, to, { loops? })` (`model.ts:404`): the shortest flow path as edge ids. An automatic move takes it; every edge is a crossing and the nodes between are skipped. A `Crossing` (`model.ts:130`) is `{ edge, from, to, at }`.
- Store (`store.ts`): `saveShape` (`:296`; takes an optional `draft` id it records on the version; checks the body, refuses with every reason, refuses a body equal to the newest, writes the next number with `parent`, `depths` and `note`, then carries open journeys and remaps open deals, all under one advisory lock), `newestShape` (`:268`), `shapeVersionsOf` (`:274`), `lock` (`:39`; one advisory lock per key, exported for drafts, tags, undo and the mirror), `shapeContext(db, triggers)` (`:245`; builds the check context from `segments` and `imports`), `diffShapes` (re-exported from `@wren/pipeline/diff`, where the pure diff lives so the web can import it without the store; nodes and edges added, removed, changed). `Refused` carries the reasons.
- `shape_versions` (`schema.ts:132`): `number` PK, `body`, `depths` (`depthOf`, stored so SQL readers read a column), `note`, `parent`, `created_by`, `draft` (the draft it was applied from, else null; migration `0309_shape_git`). The `never_edited` trigger holds it (migration `0306_shape`), as `offer_versions` and `terms_versions`.
- `shape_drafts` (`schema.ts:172`): `id` (a slug of the name, `draftIdOf`, `drafts.ts:22`; a digit-first name gets `d-`; 40 characters at most), `name`, `body`, `moves`, `base` (the version it forks), `note`, `state` (`draft`, `proposed`, `applied`, `dropped`; `DRAFT_STATES` in `history.ts`), `applied_version`, `decided_by`, `decided_at`, `drop_reason`, `created_by`, `created_at`, `updated_at`. The row changes in place; a version it makes never does.
- `shape_tags` (`schema.ts:214`): `name` PK, `version`, `note`, `created_by`, `created_at`. The `shape_tags_never_edited` trigger (migration `0309`) refuses an update or a delete: a tag is never moved or removed.
- `shape_mirrors` (`schema.ts:240`): one row per version that landed in the repo: `version` PK, `repo`, `path`, `sha`, `at`. No row means not mirrored yet.
- Drafts (`drafts.ts`): `newDraft` (`:84`; the body is not checked, a draft may be half done; refused when no shape exists, when `base` is no version, or when any draft in any state holds the id), `updateDraft` (`:125`; open drafts only; replaces body and moves), `proposeDraft` (`:144`; `draft` to `proposed`), `applyDraft` (`:168`; one transaction: `saveShape` with the draft's moves and the note, else `Draft <name>`; every `saveShape` check and "Nothing changed." pass through and the draft stays as it was; then `applied`), `dropDraft` (`:200`; a reason is required). `parseRef` (`:225`) and `bodyOfRef` (`:236`) read a ref, a version number or `draft:<id>`, to a body; `shapeDiff` takes them.
- Undo (`undo.ts`): `planUndo` (`:33`) reads the versions, runs the pure `undoChange`, and adds what needs the database: `checkShape` on the whole result, and the `openOn` refusal when an undo of "node added" would remove a node that holds open journeys ("<n> open journeys sit on <id>. Move them first."). It refuses with every reason. `undoShape` (`:86`) plans and saves under the shape's lock, as the next version with the note `Undo: <line>` (`changeLine`). The console and the CLI both go through these two.
- Tags (`tags.ts`): `addTag` (`:14`; a name of 60 characters or fewer, an existing version, a name not taken), `tagsOf` (`:46`).
- Mirror (`mirror.ts`): `mirrorShapes(db, { files, repo, workspace, log? })` (`:43`) commits each version with no `shape_mirrors` row to `mirrorPath(workspace)` = `shapes/<workspace>.yaml`, oldest first, under the lock `shape mirror`. The workspace is `wren` for the main database and the client id otherwise. The commit message is `shape <workspace> v<n>: <note on one line>` then `Author: <created_by>`. It stops at the first failure so a later version never lands before an earlier one, writes a row only for a commit that landed (a write that finds the file already holding the text takes `lastCommit`), and never throws: it answers `{ off: true }` (no token; one info line per process) or `{ committed, failed? }`. `mirrorsOf` (`:104`) lists the rows. The GitHub contents helper is core's `githubRepo` (`packages/core/src/github.ts:17`: `read`, `write`, `lastCommit`), shared with the blog box. Settings: `WREN_SHAPES_GITHUB_TOKEN` (optional; the mirror is off without it) and `WREN_SHAPES_GITHUB_REPO` (default `wrenautomation/sops`).
- `shapeWorkflow(version, body, scope)` (`workflow.ts:51`): pure; one version becomes the workflow `shape.v<n>` (`shapeFlowId`, `parseShapeFlow`, `workflow.ts:34`). Per node `k` that holds journeys: `t_<k>_<i>` (an Advance trigger as written), `m_<k>` (`journey.move`, `with.to`), `s_<k>` (`journey.stage`). A `group` source is `e_<source>` (`trigger.segment`, `entered`, `repeat: each`, kind `lead`: a person who leaves the group and comes back is a new journey) and a `sourced` source `e_<source>` (`trigger.source`), each wired to the move node of every flow edge it has. A parked source builds nothing. Inputs `in.<k>` and `in.dropped` take manual moves and drops ([[platform/journey]]).
- `shapeWorkflowsOf` (`journeys.ts:91`): the newest version plus any older one that holds open journeys. `soundShapes` (`journeys.ts:122`) drops one that fails `checkWorkflows`, with a log line. The worker passes both as `SpineDeps.shapes` (`apps/worker/src/services.ts:2125`), per workspace DB ([[platform/spine]]).
- `carryJourneys(db, toVersion, moves)` (`carry.ts:32`): an open journey on an older version moves to the new one when its node is in the new body, or is a key of `moves` (old node to new node). Else it stays on its old version: the ghost. The Map draws a removed node that still holds people as a ghost; the journey moves by its old version's edges.
- `remapDeals(db, moves)` (`carry.ts:99`): in the same transaction as the carry, an open deal whose `node` is a key of `moves` gets the new node, one step (a chain `a→b, b→c` is not followed). A journey that already has a deal at the target keeps both as they are. A won or lost deal never moves.
- `editShape` (`edit.ts:78`) with the pure `withNode`, `withEdge`, `withoutNode`, `withoutEdge`, `openOn` (`@wren/pipeline/edit`): the CLI and the console edit through these, one write path.
- `historyOf(versions, id, on)` (`blame.ts:23`): pure; one node's or edge's lines (`added`, `removed`, `renamed`, `changed`), newest first, with who, when and why. `undoChange(newest, a, b, change)` (`edit.ts`): pure; the inverse of one line of `diffShapes(a, b)` applied to the newest body; `Refused` when a later version touched that line again; the caller runs `checkShape`.

## If you change this

- **Hits:** the mirror's file name and commit message (`git log` and `git blame` in the sops repo read them; a changed path starts a new file there); `applyDraft`, `undoShape` and `importShape` (all end in `saveShape`); every open journey (carry or ghost); `checkShape` tests; `shapeWorkflow` and its node ids (a node id is a spine node id, so an arrival keeps its place); the editor's trigger notes for `trigger.journey`; the numbers views and `pipeline.number`; the board and the segment context (`shape`: nodes with depth, sources); the shape file format
- **Does not hit:** sends; the offer and terms rows themselves; a draft never touches a journey (only its apply does, through `saveShape`)
