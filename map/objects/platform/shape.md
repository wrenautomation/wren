# shape

The map of one business: a directed graph of sources, steps, offers and plans that people walk down to money (Business Map; replaces the ordered funnel). One shape per database. A version is a row of `shape_versions`, append only.

## Why this shape

An upsell or a second route into one offer is a node and an edge, not a second list. Nothing above it changes. Depth (the longest flow path from a source) gives code the order it used to read from stage position.

A node id is the spine node id, so it never goes, moves or gets renamed: versions only add and remove. A journey never arrives twice at one node in one version (`events` is unique per workflow, node and subject), so a way back is a `loop` edge: it closes the journey and opens a new one at the loop's end. Nobody sits on a source: an opening crosses the source's edge and lands on its target.

A stored body is one of two models in the same column (design language, area C1). A graph is the form the runtime runs. A **metro body** (`model: "metro"`: lines, stations, tracks, groups, frames, and optional flows) is the form the map draws. The ids are shared: a station id is the node id, a track id is the edge id (a hub track and a track into the hub have no edge of their own), an out line id is its source id, an offer line id is its offer node id. So journeys, deals, the trail and a blame follow across a convert with no remap. The runtime never reads a metro body: it reads `runOf`, which lowers one with `graphOf`. A reader that draws the map reads `metroView`.

Two additions of the metro body lower to nothing, so the run and the workflow never see them. **Attach** (`attach?: Attach[]` on a line, a group and a station): `{ kind, ref, label? }` names a sop, link, page, funnel, doc, template or note by id or `https://` URL (1 to 500 characters, no spaces; a link kind wants a URL; label up to 80). It copies no content. A **flow** (`flows?: MetroFlow[]` on the body: `{ id, label, stations, tracks }`) is a shared set of stations and tracks that a link station opens through its `flow`. A flow is its own scope: its station and track ids are unique inside it, and may repeat a body id. It holds no hub. A station or track in a flow needs no line, because a shared flow serves every line that links to it; one that names a line must name a line of the body. The other station, track, branch and order rules run in a flow as in the body. A link names a flow of the body; a flow never links to itself, and links never loop. `graphOf` and `lowerable` ignore both (a link station still refuses, so a body that links a flow cannot be saved yet). `metroOf` of a graph gives neither.

The file form (YAML) is the way to read, diff in git and write a whole version at once. The database stays the source of truth.

History works like git, without a git server in the loop. A **draft** is a body saved beside the live shape; an agent or a person writes it, proposes it, and a person applies it as the next version or drops it with a reason. **Blame** reads one node's or edge's lines from the versions. **Undo** reverses one line of a past diff on the newest body. A **tag** names a version and never moves. The **mirror** copies each version as one commit of `shapes/<workspace>.yaml` to a private GitHub repo (`wrenautomation/sops` by default), so `git log` and `git blame` read the shape's history. The mirror is a copy that catches up: a save never waits for it and never fails because of it, and the next run commits what is missing, oldest first. A draft is a row, not a git branch.
