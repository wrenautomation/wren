# Work box: CI and checks off the Mac (WA-1277)

Goal: one free arm64 box runs CI, and later the Mac's heavy checks and renders. Oracle Always Free
A1 (4 OCPU, 24 GB) from WA-1274. Oracle reclaims a box idle for 7 days (CPU p95, network and memory
all under 20%). Real work keeps it busy; there is no busy loop.

## Target

- `deploy/work-box/box-setup.sh`: the whole setup. Ubuntu 24.04, arm64 or x64, any provider.
  Idempotent. Cloud-init runs it as user_data, and `register-runners.sh` runs it again over ssh.
- `deploy/work-box/register-runners.sh [ip] [count]`: setup, then N runners (default 4), label `wren-work`.
- Workflows: `runs-on: ${{ vars.WORK_RUNNER || '<hosted>' }}`. Set the repo variable `WORK_RUNNER=wren-work`
  to move jobs to the box. Delete it to move them back. A pull request always runs hosted.
- `deploy/terraform/oracle/` (WA-1274) and `deploy/terraform/work-aws/` have the same outputs: ip, ssh_user, arch, shape.
  The AWS root is written but not applied: it bills.

What moves: every job. That is ci (lint, unit, schema, 8 integration shards, stories), contrast, deploy,
the nightly lake sync (up to 230 min) and the hourly lag check (24 jobs a day).
Why: wren goes private after the runner exists (William 11-10). A private repo pays for hosted minutes
past 2,000 a month. ~31 ci runs a day would use them in days.

Busy enough: Oracle's p95 needs the top 5% of the week (8.4 h) over 20% CPU. CI runs ~31 times a day,
and each run takes minutes on all cores. That is far more than 8.4 h a week.

## Decisions

2026-11-10, runner form. Options:

| Option | Gain | Cost |
|---|---|---|
| A. Official runner, N persistent systemd services | `container:` jobs and testcontainers work as on hosted; no GitHub credential on the box | dirty state between jobs: needs a clean timer and a chown hook |
| B. Ephemeral runners (JIT config per job) | clean workspace every job | a long-lived GitHub admin token must live on the box to mint each one |
| C. Runners in containers (myoung34 image) | box holds only docker | docker-in-docker: `container:` jobs and testcontainers networking break |
| D. actions-runner-controller on k3s | autoscale, ephemeral | a Kubernetes cluster to run, on one box |

Ranking: safe for prod secrets (deploy runs here), then jobs work unchanged, then upkeep.
Chosen: A. The box holds no token that can mint runners. The leaks A brings are handled:
`work-clean` (hourly) removes testcontainers left up for 3 h and old images, and the job-started
hook gives root-owned workspace files back after container jobs.

2026-11-10, registration. The token (one hour) comes from `gh` on the Mac and goes over ssh stdin.
It is not in user_data: the metadata service serves user_data to anyone on the box. A new token
there would also change user_data each apply. Each runner keeps its credential, so a reboot needs nothing.

2026-11-10, scope. Repo-level on wren: gh has no `admin:org` scope. Org-level would serve engine and
vireo too (both private now). To move, William runs `gh auth refresh -h github.com -s admin:org`.
Then `REPO` in `register-runners.sh` becomes the org URL.

2026-11-10, forks. wren is public until it goes private. A self-hosted runner on a public repo runs
any fork's code if a PR job lands on it. Three guards: `runs-on` sends `pull_request` to hosted; every
other trigger is push to main, schedule or dispatch; and fork PR workflows need approval from all
external contributors (set via the API).

## Risks

- The box dies or Oracle reclaims it: jobs with `WORK_RUNNER` set wait in the queue. Fix: `gh variable delete WORK_RUNNER -R wrenautomation/wren`.
- Deploy's prod secrets and AWS OIDC role are on the box during a deploy. Only code on main runs there.
- 4 runners share 4 OCPU. Integration shards queue behind gates. That is slower per run, but it costs nothing.
