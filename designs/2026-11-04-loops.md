## Rename: how

| Option | What | For | Against |
|---|---|---|---|
| A. Real rename | new service names in code; old services pruned from Restate | one name in code, logs, CLI, portal | K/V state is per name; `wren_wake('Segments/fleet')` in SQL needs a migration; every caller by string changes |
| B. Label only | keep ids, show a label in `wren loops` and Console | no risk | two names forever: the overhead he named |
| C. Rename + state copy | A, plus a one-shot copy of old K/V | keeps cursors | worth it only where state matters |

Priorities, in order: one name everywhere, then no lost work, then build cost. **Pick A.** Nearly all loops are stopped, so a rename loses no pass. Each run-set loop gets its K/V checked first; one whose state matters gets C for that loop only. Old names go in `moved` for the CLI and Console for one release.

## Judge: how

| Option | What | For | Against |
|---|---|---|---|
| A. Agent on a brief | code gathers the subject's context into one brief; a Sonnet agent judges; the answer keeps `why` and the agent's id | fits "agent drives, code is tools" and "brief carries lean data"; one call a subject | the brief must carry all it needs |
| B. Agent with tools | an agent per subject that reads the lead's research and the thread itself | finds context the brief missed | many calls a subject; slow; costs more |
| C. No machine judge | William's queue only | no spend | no picks; nothing to learn from |

**Pick A.** Comment quality fits a brief (the post, the draft, the account). Lead fit fits one too (the offer, the company's research summary). The `decide()` seam stays: the backend `jev` is replaced by `agent` for `comment_quality` and `lead_fit`. His calls stay beside each answer. Jev keeps a backend slot for profiling and segmentation trials only.

Spend: about 700 subjects a month on Sonnet, a few dollars. Money is William's call.
