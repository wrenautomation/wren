## Goal

Raise how many experiments we run per hour, so the spread of AI output stops mattering. The agent
makes many samples; William marks the good and the bad and says why; the agent makes the next batch
from that. Winners and proven tips are kept and reused. Copy first, then video edits, designs and
landers. Later, the same subjects take live data (split tests per segment).

William's words: "most of it is generated, most of it is view only, and the person's job is just
to select ones that are good" … "give guiding prompts really easily" … "build a catalog over time"
… "start experiments from scratch or from my direction" … "heavily reliant on the chat agent, like
Birdwatch".

## Target shape

```
Birdwatch study ─┐          ┌──────────── chat agent (skill: variants) ────────────┐
SOPs, skills ────┼─ guides ─▶ reads brief, guides, feedback → makes N samples      │
William's tips ──┘          │ (copy, studio renders, images, pages) → `variants add` │
                            └──────────────▲──────────────────────────┬────────────┘
                                           │ `variants feedback`      │ batch open
                                    marks, notes, stats               ▼
                            ┌────────────────────────────────────────────────────────┐
                            │ portal: Campaigns › Variants  (Today shows "To pick")   │
                            │ batch of full samples, blind; Amazing / Good / Bad;     │
                            │ mark a line, a region or a moment; one note per batch   │
                            └────────────────────────────────────────────────────────┘
                 keep → catalog (best samples per subject)   lock → guide is a rule (SOP)
```

The agent drives (rule 10-28). Code is tools: the ledger, the CLI (JSON out), the review page, the
ranking maths. The agent decides what to make, which guides to try, and why; each batch and sample
carries that why and the agent's id.

## Nouns

| Noun | Is |
|---|---|
| Subject | One thing we iterate on: "Birdwatch promo cut", "opener email for recruiters". Kind: `text`, `image`, `video`, `page`. Has a brief (William's direction or blank), optional seeds (a study slug, a sample to start from) and a status. |
| Batch | One round of N samples the agent sends for review, with the agent's why. Status `open` (waiting for marks) or `closed`. |
| Sample | One version. Text inline, or a file in the media bucket (image, mp4 with a poster, html). Has a parent sample, the guides it applied, a change note, the agent id. |
| Verdict, note | William's call on a sample: `amazing`, `good`, `bad`, or a note only. Optional anchor: a text quote, a box on an image (fractions), a time range on a video (seconds, optional box). |
| Guide | A tip or rule the agent writes from. Source: a study claim, an SOP, a skill, William. Scope: one subject, a kind, or everyone. State `testing`, `locked`, `dropped`. |
| Catalog | Kept samples (William's keep, or a winner the stats back), with their subject and kind. |

## Ranking

Each closed batch is a partial ranking: amazing > good > unmarked > bad. Plackett-Luce (MM fit,
pure, in `@wren/experiments`) turns all batches into one strength per sample (options below). A guide's effect is
the good-or-better rate of samples with it against samples without it, with the count, and "too
early" under 30 samples. Live data (replies, plays, signups) later feeds the same samples through
the existing bandit; a page split already exists (`site_splits`).

### Where William reviews

later, then build cost.

| | Shape | For | Against |
|---|---|---|---|
| **A. Portal page (chosen)** | Campaigns › Variants, Today › To pick | everywhere, signed in, same data as the CLI, client-ready | most build: routes, page, UI proof |
| B. claude.ai artifact with its own db | like the blind-pick page | fastest | data outside wren; the CLI cannot read it; no clients |

### How the agent writes the next batch

| | Shape | For | Against |
|---|---|---|---|
| A. Fixed genetic operators in code | swap a block, cross two parents | repeatable | text, video and design have no shared "block"; ignores William's notes |
| **B. Agent reflects (GEPA-style, chosen)** | the agent reads marks, anchored notes and guide stats, says what to change, makes the batch | works for any kind; uses William's words | depends on the agent; each batch must log its why |

GEPA (MIT) is the model for the reflection step and for keeping several winners when segments
differ. TextGrad's idea is the anchored note: feedback on one line, region or moment.

### Tenancy

Ranked priorities: a client's data never leaks; one code path; cost.

| | Shape | For | Against |
|---|---|---|---|
| **A. Client's own database (chosen)** | no client column; `--client` picks the database; same migrations | isolation is the database's, no filter to forget; matches how client data lives now | a cross-client catalog needs a query per database |
| B. `client` column in main | one database, filter on every query | one catalog across clients | one missed filter leaks a client's copy; needs RLS to be safe |

### Data path to the page

Ranked priorities: the agent and the page see the same rows; phone and iPad; client-ready.

| | Shape | For | Against |
|---|---|---|---|
| **A. Restate console service (chosen)** | Postgres → `VariantsConsole` → portal Worker `/api/variants/*` | same auth, audit and signing as every console; deploys with the Lambda | one hop more than a direct read |
| B. Local server from the CLI | `wren variants serve` | no deploy | Mac only; William reviews on the iPad |
| C. Artifact with its own db | claude.ai page | fastest | data outside wren; CLI cannot read it |

### Media

| Layer | Options | Chosen and why |
|---|---|---|
| Store | inline base64 / s3 + signed GET | s3 + presigned GET: the bucket and signer exist; rows stay small |
| Video player | shared `PlayerSlot` / native `<video>` per sample | native: a batch shows 4-6 cuts side by side; PlayerSlot plays one item at a time |
| Region marks | Annotorious (BSD) / small custom box layer | custom (~60 lines): one layer serves image, page and a paused video frame; Annotorious has no video |
| Page samples | iframe `src` from s3 / `srcDoc` sandboxed | `srcDoc` with `allow-scripts` only: no same-origin, so a page cannot read portal cookies |
| Anchors | own shape / W3C Web Annotation selectors | W3C-shaped subset (quote, box, time): known meaning, easy to export |

### Ranking

| | Shape | For | Against |
|---|---|---|---|
| A. Good rate only | count good / judged | simple | ignores which batch was harder; no order inside a tier |
| **B. Plackett-Luce over tiers (chosen)** | MM fit, prior of one win and one loss vs a reference | uses every batch as a partial ranking; one scale across batches; se from Fisher information | a sample seen once has a wide se |
| C. Elo / TrueSkill | pairwise updates | streams well | order-dependent; pairs, not tiers |

## Phase 2: sync and live data (WA-1067.11, 11-05)

### Sync: cuts of one footage, played in step

A sample's `source` = `{ref, spans}`: the footage (`studio:<edit id>`) and the source ranges it
plays, in play order. The CLI fills it from a studio edit (`studio: {edit, format}` in batch.json:
`keepSegments`, plus `shortCutsOver` for a Short). Pure maps in `@wren/variants/sync`
(`toSource`, `toPlay`, `nextKept`), shared by the page and the agent.

| | Shape | For | Against |
|---|---|---|---|
| **A. Leader/follower (chosen)** | the video you touch leads; others seek to its mapped time, drift over 0.15 s re-seeks; followers muted | native controls stay; any cut can lead; no clock to own | a follower lags one frame after a seek |
| B. One master clock | a hidden timeline drives every video | exact | replaces native controls; seeking one cut must move a clock it does not own |
| C. One composed video | render the cuts side by side | perfect sync | a render per batch; no per-cut notes or boxes |

Modes: Apart, Same moment (footage time; a cut that dropped it shows "Cut here"), Same clock
(output seconds). Same moment shows only when every cut has spans over one footage. Footage lanes:
each cut's kept spans on the footage line, the leader's playhead, tap to send all cuts there.

### Live data: what the market says, per segment

| | Shape | For | Against |
|---|---|---|---|
| **A. Outcome ledger (chosen, William)** | `ships` (sample → post, site page, email `template@version`) + `outcomes` (ship, segment, day, metric) filled by `VariantsCollect` every 6 h | channels untouched; one read for every channel; history by day | a copy of numbers the channels hold |
| B. Read through | `live` queries each channel's tables on demand | no copy | every channel's shape in the read path; slow over many ships |
| C. Bandit allocation | traffic moves to the winner as results come in | fewer sends to losers | email at 1-3% replies converges in weeks; build later on A's data |

Segments: post `platform:`; site `channel:`, `source:`, `campaign:` (site events in the ship's
window); email `niche:`. Every ship writes `all` plus its breakdowns. Rates: Wilson 95% range;
P(best) from `@wren/experiments` posteriors per channel × segment × rate. Post means
(`avg_view_pct`, ...) weighted by views. The page shows each shipped sample's rate beside his
verdict and taste rank, so taste and market can be compared.
