# Test trim: fewer, stronger tests (WA-1397)

William 11-15: "do the trim ... all tests across the board for everything wren"; "i suspect uve been overzealous with test quantity".
Scope: wren (apps, packages, scripts) and aerie. Engine, autobrowse, vireo and peers have their own sessions: not in scope.

## Baseline (CI main, 4 runs to 11-16 00:49Z)

- Tests: 9,293 in 1,018 files, 195k lines; source is 474k lines. Stories: 95 files, 566 story tests.
- Unit about 5,200, 1 red. Integration 3,074, 25 red (24 in all 4 runs). Stories 6 red (map, confirm, side panel).
- Tests report only since WA-917 (`2026-10-27-test-audit.md`), so nothing makes a test earn its upkeep.

## Options

1. Red and slow only: delete what fails or takes the most time. Small cut (about 30 tests); it keeps every duplicate.
2. Rubric by reading (chosen): read each file, cut by the rules below. It costs reading time, and the cut follows what each test proves.
3. Coverage-guided: delete a test whose lines other tests already cover. No coverage config exists, and lines covered are not behaviour checked: a covered line with no assert still counts.

Priorities, in order: a kept test catches a real break; less upkeep and run time; no prod bug hidden by a delete.

## Rules

- Keep: isolation, sends, money, migrations and schema, external contracts (peers coord contract, Backlog.md goldens, route shapes), and a test named for an incident.
- Cut: one behaviour asserted at two or more layers (keep the layer that owns it); a test that restates the code (all mocks, call arguments, a schema or type echoed back); near-equal `each` rows (keep the edges); spawned end-to-end runs past one smoke test per CLI.
- A red test: stale → delete or rewrite; the code is wrong → fix it or file a task. Never delete a red test without one of those lines.
- Stories stay (the UI proof). Only redundant play asserts go.
- After each package: run the kept files, run the guards alone (a delete can leave an unread export), and grep scripts and CI config for a deleted path.
