# Egress: one Wrenfile, a sandbox for agents, a proxy for the Mac (WA-1194)

## Goal

Every process that can reach the internet has a written list of where it may go. One file holds every list. Agents cannot read secrets and cannot send outside their list. Open-web readers cannot reach this Mac's own services or the LAN. Each decision is logged, so a list grows from facts, not guesses.

Target state:

```
Wrenfile ──► wren egress apply ──► smokescreen, one per role (launchd), ACL per role
   │                                  ▲ HTTPS_PROXY
   └──► relay, at each launch ──► claude (agent) ─► Bash in the OS sandbox (Seatbelt), hosts + denyRead
                                         └─► its CLIs (weaver, vireo): outside the sandbox, through the role's proxy
desk worker (Node), weaver serve ──► through their role's proxy
```

## Threats, in order

1. **Agent exfiltration** (the lethal trifecta): an agent reads untrusted web text, holds private data, and can send. A page tells it to post `~/.aws` or a ledger to a host.
2. **SSRF from open-web readers**: a URL or a redirect points at `127.0.0.1:4748` (the relay starts agents), `:4747` (weaver serve), `:9222` (Chrome CDP), `:3100` (canvas), the LAN, or a metadata IP.
3. **A beacon in a dependency**: a daemon's package sends data to a host nobody listed.

## Industry practice

- Default-deny egress per workload, through a forward proxy that knows the caller's role: Stripe smokescreen, Envoy, Squid. Run report mode first, read the misses, then enforce.
- SSRF: deny by the resolved IP (loopback, private, link-local, metadata), not only by name.
- Agents: an OS sandbox on the shell (Seatbelt or bubblewrap, gVisor or Firecracker on servers), a network allowlist, and no secrets the agent can read. Best case, the proxy adds the credential on the way out, so the agent never holds it. Remove one leg of the trifecta where you can.
- Ingress (not built here): keep Better Auth for sign-in. For "who may do what", Cedar (AWS, policy as code) or OpenFGA (Zanzibar-style relations). Our `can()` grants are enough today.

## Options

Ranked priorities: real enforcement where it matters (agents) > one source of truth > no new daemon that can take prod down > $0 > little code.

**Agent boundary**

| | How | For | Against |
|---|---|---|---|
| A1 | Claude Code's own sandbox, set per setup (`settings.sandbox`) | OS-enforced; srt is its engine; the relay already passes it; the portfolio maker uses it today | Covers the shell only; the Read tool needs permission denies |
| A2 | Wrap `claude` in `srt` | Covers Claude's own calls too | Claude's sandbox cannot start inside another Seatbelt profile |

**Pick A1.** Read gets `permissions.deny` for the same secret paths.

**Mac daemons**

| | How | For | Against |
|---|---|---|---|
| B1 | smokescreen, release binary, one process per role | Stripe's, in prod since 2016; open, report, enforce; SSRF deny by resolved IP built in; JSON decision log; no Go build | Processes must honor `HTTPS_PROXY`: a library with its own agent goes direct |
| B2 | srt wraps each daemon | OS-enforced, file denies too | Nested Seatbelt fails for the relay (its agents sandbox) and the desk (Chrome) |
| B3 | Envoy or Squid | Mature | Heavy config for four roles |
| B4 | LuLu app firewall | OS-level, free | Rules per binary; every daemon is `node` |

**Pick B1.** It is not a hard boundary: a hostile package can skip the proxy. A1 is the hard boundary for agents. The OS-level fix for daemons, later: run them as their own macOS user, with a `pf` rule that lets that user reach only the proxy port.

**Role identity**

| | How | For | Against |
|---|---|---|---|
| R1 | One port per role | Any client works, Chrome too; vanilla binary | One process per role |
| R2 | Proxy user name (`http://desk@…`) | One process | Chrome cannot send it; needs a Go build |
| R3 | mTLS client cert | Stripe's way | Cert per role; clients need TLS to the proxy |

**Pick R1.** Any local process can pick any port, so a role is a label, not a boundary.

**Where the policy lives**

| | How | For | Against |
|---|---|---|---|
| P1 | One `Wrenfile` in wren; the relay reads it at launch; `wren egress apply` writes the ACLs | One source; reviewed in git | wren is public: lists must hold no client names |
| P2 | Each enforcer by hand | No code | Lists drift apart |

**Pick P1.**

## Shape

**`wren/Wrenfile`** (YAML):

- `secrets`: paths no agent shell may read (`denyRead`) and no agent may `Read`.
- `roles.<name>`: `port`, `mode` (`open`: any public host; `report`: any public host, logs a miss; `enforce`: listed hosts only), `hosts`. Every role blocks loopback, private, link-local and metadata IPs.
- `agents.<setup>`: `role` (whose proxy its claude and CLIs use), `run` (CLIs that run outside the sandbox: they need the role's hosts), `hosts` (what its sandboxed shell may reach). `agents.default` covers a setup with no entry.

**`@wren/egress`**: parse and check the Wrenfile; compile a role to a smokescreen ACL, a setup to `settings.sandbox` + `permissions.deny` + proxy env; read the decision log.

**Relay** (`@wren/agent` launch): merges the setup's compiled sandbox under the setup's own `sandbox` (a setup may add, never drop a secret), adds the denies and the role's proxy env. If a role's proxy is down, the relay logs a warning at start, and the child's calls fail on the dead port: fail closed. The fix is `wren egress apply`.

**`wren egress`** (JSON out):

- `check`: what each role and setup compiles to.
- `apply`: installs smokescreen (pinned version, SHA-256 checked), writes `~/.config/wren/egress/<role>.{acl.yaml,env}`, one launchd job per role (`com.wrenautomation.egress-<role>`, KeepAlive), removes jobs of dropped roles, probes each port.
- `status`: each role up or down, its mode, decisions in the last day.
- `log [--role] [--misses] [--since]`: decisions grouped by host. An agent reads the misses and proposes hosts; William approves a change to `enforce`.
- `env <role>`: the proxy env lines, for a process started by hand (`weaver serve`).

**Desk worker**: `install.sh` adds `~/.config/wren/egress/desk.env` to the plist when the file exists. Chrome stays direct: the open web is its job, and it has its own sandbox.

**Roles at start**: `agents` for claude's own calls and the vireo CLIs (report), `weaver` for weaver serve and the weaver CLIs (open: SSRF guard only), `desk` (report). Agent shells: no hosts. After a week of logs, `agents` and `desk` move to enforce, on William's yes.

## Not in this build

- Lambda egress (option C, about $32/mo for a VPC NAT and the proxy): waits on William.
- A proxy that adds credentials, so no process holds a key: credvault `designs/2026-11-08-gate.md` (WA-1196).
- Hard lock for daemons: see below (WA-1197).
- Other Mac jobs (peers view, canvas, autotrack, internships): they join by role once the first three run clean.

## Hard lock for daemons (WA-1197)

B1 is soft: a package that skips `HTTPS_PROXY` goes direct. Options to make it hard, all $0:

| | How | For | Against |
|---|---|---|---|
| H1 | pf `user` rule: each daemon runs as its own macOS user; that user may reach only its proxy port | Kernel-level; covers the desk with Chrome | Needs William's sudo once; a daemon off his user loses his Keychain (credvault's seal key), his Chrome profile and `~/Documents` (TCC); large migration for the desk and the relay |
| H2 | Seatbelt per process: `sandbox-exec` profile, `(deny network-outbound)`, allow loopback only | No sudo; per process, not per user; tested 11-08: direct curl refused, through the proxy 200 | Seatbelt cannot nest (tested: `sandbox_apply: Operation not permitted`), so not the relay (its agents sandbox) or the desk (Chrome sandboxes) |

**Pick H2** for weaver serve and the CLIs agents run outside their sandbox (`weaver`, `vireo`, `folders`, via a shim in the setup's bin dir). The relay and the desk stay soft. The key gate (credvault WA-1196) limits what a skipped proxy can take there: stand-ins, not keys. H1 waits until a daemon needs it.
