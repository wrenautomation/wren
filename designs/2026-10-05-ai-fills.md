# AI fills: casual names and prompt slots in templates (2026-10-05)

## Answer first

- A **fill** is a fact a model writes, checked by code before any email can use it. Two kinds:
  1. **Casual names**, always on: `company_name`, `company_short` and `first_name` as a person would say them. No Inc or LLC, no made-up initials ("ASS" for Assertive Staffing Services), no shouting caps, no city or tagline glued on, no "Sales" or "Michael.Stenger" as a first name.
  2. **Prompt slots** in a template: `<<In 3 to 6 words, the kind of roles {company_name} fills>>`. The prompt is part of the template, so the template's version changes when the prompt does.
- The model sits behind the `@wren/llm` seam (`makeLlm`). Prod `WREN_FILL_LLM=cohere` (Command A on the Cohere credits; William, 10-05: "a super basic casualization task"). Any `makeLlm` spec swaps it.
- **The model proposes, code disposes.** A casual name may only use words from the filed name, in any case. A first name must be part of what was filed. A slot answer is one line under a word cap, with no link, no dash and no number the prompt didn't hold. A failed check means the fact is missing. A missing fact drops its `(( ))` group, falls back where the template gives one (`{first_name|there}`), or keeps the company out. It never ships the rule-based guess.
- Every answer, including refusals, is cached in Postgres (`fills`), keyed by kind, prompt version and input. The same name costs one call ever. A changed system prompt starts a fresh cache.
- Compose, the queue refresh and reply drafts all fill through the same `Filler` before the pure `render()`. Render stays pure: a fill is a fact like any other.
- **Why:** on 10-03 William asked for an AI casualization layer (outbound-copy notes). Only the rule half got built. The 10-05 audit over 32,031 prod recruiting names showed it fails: 2,118 made-up initialisms, 281 with legal forms left in, cities filed as firm names ("Odessa, TX"). Of 213 queued recruiting openers, 34 carried a bad name ("BES", "GET", "Contact 1"). The 4 already sent were clean.
- Cost: Command A is $2.50/M input, $10/M output. A call is ~450 tokens in and ~25 out, so ≈ $0.0014. One company call plus one person call per enrollment ≈ $0.003. 1,000 enrollments ≈ $3 of Cohere credits. A cached name costs nothing.

## 1. Casual names

One call per company name and one per person, each with its own system prompt (`CASUAL_COMPANY`, `CASUAL_PERSON` in `outreach/fills.ts`). The answer is JSON.

| kind | input | answer | check |
|---|---|---|---|
| `company` | the readable firm name (`readableCompany`) | `{"name": "...", "short": "..."}` or `{"name": null}` | every word of `name` and `short` appears in the input (case-insensitive; `&` and `and` match); at most 6 and 4 words; no legal form; an all-caps word must be all caps in the input too |
| `person` | the filed first name and full name | `{"first": "..."}` or `{"first": null}` | one word, letters, `'` or `-`, 2 to 20 letters; it appears in the input; not a role word ("Sales", "Manager", "Info") |

`name` replaces `company_name`, `short` replaces `company_short`, and `first` replaces `first_name`. A refusal (null, or a failed check) removes the fact.

The rule-based `shortCompany` stays for pure renders with no database (tests, the spamcheck sample). It no longer makes initials: a name made only of plain words stays whole.

## 2. Prompt slots

Template mark: `<<prompt>>`. The prompt is plain text and may quote facts as `{key}`. It compiles to a field whose key is `ai.<12 hex of the prompt's hash>`, carrying the prompt. Everything a field does, a slot does: required by default, dropped with its `(( ))` group, makes a variant option ineligible when missing.

- **Filled:** the prompt with its facts substituted is sent under the `SLOT` system prompt. A slot quoting a missing fact is not sent; it is missing.
- **Check:** one line; at most 25 words; no URL, `@`, em or en dash, brackets, braces or quotes; no digit absent from the prompt; not "none".
- **Version:** the key carries the prompt hash, so any prompt edit is a new template version (queued email re-renders on deploy).

## 3. Cache: `fills`

| column | |
|---|---|
| `id` | serial |
| `kind` | `company`, `person`, `slot` |
| `prompt_version` | 12 hex over the system prompt and the check's version |
| `input` | the text sent (resolved prompt for a slot) |
| `key` | sha256 of kind, prompt version and input; unique |
| `value` | jsonb answer after the check, null when refused |
| `refused` | why, when refused |
| `model` | the `LlmClient.name` |
| `envelope` | `raw_text`, `api`, `call` (the `@wren/llm` envelope) |
| `created_at` | |

A provider failure (`LlmError`) aborts the pass, as in every LLM stage; the next pass retries. A garbled answer is not stored: the fact is missing this pass and asked again next.

## 4. Wiring

- `Filler.fill(facts, templates)` returns new `Facts`. `makeFiller(db, llm)`. The model reads the name as stored (`Facts.filed`), before `readable` cut it.
- `compose`, `refreshQueue` and the reply drafter take `fill?: Filler`. The worker builds one from `WREN_FILL_LLM` and passes it to the queue-keeper, the deploy refresh, evolution's refresh and replies. Prod sets `WREN_FILL_LLM=cohere`; the default is `none` (config never defaults to a paid provider). A client campaign gets no filler: the cache is in main's database, and a client's names stay in the client's.
- A refresh warms the cache over its whole queue first, 4 calls at a time (Cohere allows 500 a minute; 8 ran near 450). The first run after deploy: 209 queued enrollments ≈ 420 calls ≈ 2 minutes.
- `LlmClient.complete` gains `system` (`CompleteOptions`). AI SDK providers pass it as the system message; `claude-code` uses it as `--system-prompt`.

## 5. Not doing

- No LangGraph: one call per fill, no loop.
- No nicknames ("Robert" stays Robert). The model may only cut, recase and pick.
- No rule-based fallback when a fill refuses: refusing is the point.
