# Ads audit

2026-10-06. William: "the rules for new accounts with no history is good, audits are good, we should plug that into wren ads to prepare."

## What

`wren ads audit [--json]` → `Ads.audit`. Read-only. Reads the ad account, campaigns, ad sets, ads, pixels, the last 7 days, and a conversion window that ends `conversionLagDays` ago. Returns cold start per dimension, scored controls, coverage, a grade and draft fixes. Writes nothing to Meta and stores nothing.

## Contract (claude-ads, MIT, Copyright (c) 2026 agricidaniel)

- Cold start per dimension, never inferred across them:
  - account: cold only on zero lifetime spend with no recent impressions. Zero spend plus impressions is contradictory, so `unknown`.
  - pixel: cold when no usable pixel has ever fired. A new account doesn't prove a new pixel.
  - conversions: cold when the lag-mature window shows no accepted conversion.
- Any cold dimension turns off history rules (fragmentation; objective alignment when conversions are cold) and adds three drafts: validate measurement, creative as hypotheses, staged reversible tests.
- Control states: pass, fail, unknown, not_applicable. Weights: critical 5, high 3, medium 1, info 0.
- Category health = pass / known. Coverage = known / applicable. Overall health is weighted by category (measurement 25, creative 25, structure 20, audiences 15, delivery 10, policy 5), renormalized over the categories present.
- Grade by coverage: ≥80% graded, 60–80% provisional, below that insufficient. Unknown critical controls are always listed.

## Controls

| id | severity | fails when |
|---|---|---|
| policy.account_status | critical | account_status ≠ 1 |
| policy.disapproved | high | an ad is DISAPPROVED or WITH_ISSUES |
| measurement.pixel | critical | an ad set optimizes for website events and no usable pixel exists |
| measurement.pixel_firing | high | no pixel fired within `pixelStaleDays` |
| measurement.utm | medium | a creative lacks utm url_tags |
| creative.formats | medium | one format only |
| creative.per_adset | high | an ad set has fewer than `minAdsPerAdset` ads |
| structure.objective_goal | high | an ad set's goal doesn't serve its campaign's objective |
| structure.fragmentation | medium | more than `maxAdsetsPerCampaign` ad sets in a campaign (warm only) |
| delivery.learning | high | a live ad set is learning limited |
| delivery.budget_use | medium | 7-day spend under `minBudgetUse` of live budgets |

Scope is live (ACTIVE) objects. When nothing delivers, the paused setup is checked instead, so a launch can be audited before `start`.

## Knobs

`ads.meta` settings (Shop → Meta ads): `pixelStaleDays` 7, `minAdsPerAdset` 3, `maxAdsetsPerCampaign` 5, `minBudgetUse` 0.7, `conversionLagDays` 7.

## Hypothesis (first use)

Expected to change: thresholds per account (settings); an audiences category once custom audiences are read; per-client accounts when `ads.meta` goes per client. Fixed: read-only, drafts never applied.

## Decisions

- Not stored. One run is cheap (7 Graph reads); history can come later as `ad_audits` if the console wants a trend.
- Reads in turn, not parallel: each is a journaled Restate call.
- One page of 200 per list. Enough at Wren's size; paging when an account outgrows it.
