# The cache

2026-10-11. William's temp notes: "cache… redis… write through/back, CDNs" and "post counts are
a bit off (probably will fix propagation delays with the cache)".

## Decisions

- **Post counts were a cadence problem, not a cache problem.** Stored YouTube views matched the
  platform at read time; a post was looked at once a day. Now, on free API reads, a post is
  looked at hourly for 2 days, every 6 hours to a week, then daily (`LOOK_TIERS`,
  `content/metrics.ts`). X bills each read; LinkedIn and Reddit read through a browser: daily.
- **Valkey on the box**, not ElastiCache: $0, next to Postgres, the same shape as PgBouncer.
  Valkey, not Redis: the open-licensed fork, same protocol.
- **Postgres is the truth; the cache only saves a read.** Read-through with a TTL
  (`readThrough`), and a write that changes the truth deletes its key (`invalidate`).
- **Never write-back.** A value held only in the cache is lost on a restart; nothing here is
  worth that. Write-through is just write to Postgres, then invalidate.
- **Never a secret.** The cache sits outside the key store's KMS encryption. OAuth access tokens
  stay in each process's memory.
- **A down cache is a miss.** Every cache error falls through to the load; one warning a minute.
- **No disk.** `save ""`, no AOF: a restart empties it.
- **CDN: Cloudflare, as now.** Pages for the lander, R2 and S3 behind it for media, `caches.default`
  in the portal Worker. Nothing to add.

## Shape

- `deploy/scripts/box-valkey.sh`: container `wren-valkey`, TLS on 6380 with the box's self-signed
  cert, 64 MB, LRU out. One login allowed only GET, SET, DEL, PING on `wren:*` keys. Password in
  SSM `/wren/prod/cache`; CI reruns it each deploy, idempotent.
- `WREN_CACHE_URL` (env-2): `rediss://default:<pw>@<box ip>:6380/?fp=<sha256>`. The client pins
  the cert's fingerprint and sends the password only after it matches.
- `@wren/core/cache`: `Cache` (memory or Valkey), `readThrough`, `invalidate`. `@wren/core/resp`:
  a small RESP2 client, no dependency.
- First user: the console's Restate admin GETs (service list, OpenAPI), 5 minutes, shared by
  every Lambda.

## Next users, when measured

A screen whose Postgres read is slow under load, or a third-party read that rate-limits us.
Add the key next to the write that changes it.
