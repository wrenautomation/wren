# Checks: success criteria for every unit (2026-10-05, proposal)

Proposal for William to agree before code. William: "should have some rigidity / consistency / low failure rate for consolidating enrichment sources, and making sure source actually give us the same people... im thinking things like prehook and posthook validations, so that things actually match (some way to assure results are right and retry if not since restate takes care of retries but might not take care of success criteria)".

## Answer first

- Restate retries a step that throws. A step that returns a wrong answer counts as done. So the checks have to be ours.
- **Proposal: one `Check` part with three hooks per stage.** `before` decides a unit is worth spending on. `after` decides its result is right before anything is written. `agree` compares sources that speak about the same fact. A failed `after` tries the next source on the stage's ladder. When the ladder runs out, the unit is **held** with its reason instead of retried forever.
- **Disagreement is a state, not a winner.** When two sources disagree about a person, the fact is `conflict`. A brief doesn't use a conflicted fact, and a third source settles it.
- **Every check is counted** per stage and source, so the Watch shows pass rates. A source whose pass rate falls pauses itself, the way a domain's plain-test rate under 80% pauses its sends.
- Cost: the checks are code, $0. Settling a conflict is one more Exa read, paid from the keys' free monthly credit ($10 a key), so $0 while the ring has room.

## What exists

- **Identity checks, one per stage, each its own shape:**
  - A LinkedIn company page counts only when its website is the firm's registrable domain (`firmSite`).
  - A person's role counts only when the company name is the firm's (`isFirm`).
  - A model's claim stands only on words found on a page we read (`grounding.ts`).
  - A mailbox verdict mints a fact only when its verifier is authoritative.
- **Retries:**
  - Discovery and enrichment units retry 3 times, then count as failed.
  - Scan and contacts retry until they land, by design.
  - YouTube had no cap, so one firm whose description was cut mid-emoji failed the same way on every retry and blocked the pool (fixed 2026-10-05 with `pgSafe` and a 3-try cap).
- **Agreement:** none. Findings upsert on their key, and a reader picks the highest confidence. On the demo client, 9 leads are "still there" by search while their own mailbox rejects mail. Today search wins those (0.8 against 0.6), so the brief says they are still there.

## The shape

```ts
interface Check<In, Out> {
  name: string;                       // "team-search: person works at the firm"
  before?(input: In): string | null;  // why not to spend; null = go
  after(input: In, out: Out): string | null; // why the result is wrong; null = keep
}
```

- **Where it runs:** inside the unit, around the source call. A failed `after` throws a `CheckFailed` that the stage's ladder catches to try its next source (cache, then Google, then Exa, as `lookUpCompany` already does). When the ladder is out, the unit returns `held` with every reason tried.
- **Held units:** a row in `unit_holds` (stage, subject, reasons, until). Selection skips a held subject until `until`, 7 days by default. The Watch lists holds by stage and reason, and a person can release one.
- **Poison units:** every unit loop gets a retry cap. A terminal error after it is a hold with the error as its reason, so one bad row never stops a stage.
- **Counting:** each check outcome adds to `check_counts` (stage, source, check, day, pass, fail). Under 70% passes over the last 50 units pauses that source on that stage, and the Watch says why.

## First uses

1. **Person still at the firm** (`agree`). Search, LinkedIn cache and mailbox each give a reading. Two agree: confidence up. They disagree: the fact is `conflict`. The brief treats it as unknown, and one more read settles it: a fresh search, or the mailbox again after 7 days. This covers the demo's 9.
2. **Team search** (`after`). A person found by Exa counts only if their current role is the firm by name, or their email is on the firm's domain. Today a name match alone counts.
3. **Company page** (`after`). Already checked by domain; it moves into the shared shape and gets counted.
4. **Lists from autobrowse.** The records op already works this way: rows checked, re-written on a drop, failed when it can't be fixed. Its holds and counts land in the same tables when wren runs it.
