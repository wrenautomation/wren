# Portal inventory, 2026-10-19

Read-only survey of every portal route before the reshape (designs/2026-10-19-portal-reshape.md). Generated by an Explore agent; kept so the "usage list before any deletion" rule has its list. Usage: the portal records no page views; see the reshape doc for the 30-day write activity per table.

I found 243 distinct page routes across 31 apps. The router has no per-page route table. Every page is declared as data in `modules/*/index.ts`, and the sidebar is built from those declarations.

## 0. How routing works

- **Router:** `apps/portal/web/src/router.tsx` (175 lines), TanStack Router with code routes. There are only four route shapes:
  - `/`
  - `/$app`
  - `/$app/$page`
  - `/$app/$page/$`, a record's own page or a deeper place
- **Page lookup:** `/$app/$page` is resolved against the `MODULES` array in `web/src/modules/index.ts` (30 distinct app ids, 290 page declarations, 243 distinct `app/page` pairs).
- **Where the table's pages come from:** every page is a `ModulePage` from `web/src/module.ts`. It is either a hand page (`Page: Component`) or a template page (`template: list | queue | form | shop | overview | day` plus `record:`).
- **Redirects:** `web/src/moved.ts` sends `/marketing/{engage,dms,invites,people,threads,places,accounts,dm-copy}` to `/outreach/*`. A page's `legacy()` rewrites old query params.
- **Pages outside the router:** `web/book.html` runs `web/src/book.tsx` (723 lines) at `/book`. `web/replay.html` runs `web/src/replay.ts` (216 lines) at `/replay`. The Worker `apps/portal/src/worker.ts` routes `/o/*`, `/__pay/*`, `/go/*`, `/oauth/*` and `/api/*`.
- **Today (`/`):** `web/src/today.tsx` (471 lines). It reads `console/recordsTypes`, `console/recordsList`, `console/recordsCounts` (via `waiting.ts`) and `delivery/me`. With one visible app, `/` redirects to that app's first page.
- **Template pages (the file for every list, queue, form, shop, overview and day row):**
  - `web/src/records.tsx` `TemplatePage` is 980 lines.
  - It renders the `@wren/ui` templates `records.tsx` (3490 lines), `overview.tsx` (560), `queue.tsx` (373), `form.tsx` (111), `shop.tsx` (370) and `day.tsx` (412).
  - Rows below say "tpl:list", "tpl:queue" and so on, with the record type and the declaring `modules/<app>/index.ts`.
  - Data for these is `<product>/recordsList|recordsGet|recordsStats|recordsCounts`, where product is the record prefix. It is `console/*` for Wren's workspace and for `access.*`.
  - The router loader prefetches only list and queue pages (`prefetchPage`).

**Visibility rules (`can()` in `packages/ui/src/access.ts`, applied in `App.tsx` `shown()`):**
- `audience: team` shows only to Wren's team.
- `audience: client` shows to signed-in clients and never on the demo.
- `audience: demo` shows only on the demo.
- `needs` and `at` check a permission.
- Client workspaces see an app greyed ("off") unless its `component` is installed in the Marketplace.

## 2. Page inventory

**Key to the nav-section column:**
- "tab" means a sidebar or tab entry.
- "btn" means a header button.
- "link-only" means `hidden: true`, with no tab, reached by link, tile, ⌘K or a lit parent tab. These are the unlinked routes. Section 3 lists how each is reached.
- "(More)" means it is linked from Marketing → More.
- An `[Group]` suffix is the sub-heading in the sidebar.

**Reading the data column:** "rec X" is a template page over record type X, served by the record prefix's product. A plain call such as `delivery/home` is a hand page's direct API call. The Purpose column holds only a short phrase per page.

## 5. Feature flags and env vars

- **No page or route is gated by a feature flag or env var.** There is no `import.meta.env` in the web app.
- **One action is flagged.** The Marketing post-now action `marketing.postNow` carries `requires.flag = POST_NOW`, imported from `@wren/core/marketing/console-routes` (`modules/marketing/index.ts` lines 7, 2087 and 2172). The flag decides the "Post now" action, not the page.
- **Gating mechanisms that act on pages:**
  - `requires.audience` (`team`, `client`, `demo`).
  - `requires.needs` (`manage`, `money`, `team`, `run`, `read`) with `at`.
  - Module `component` install state.
- **Flags come from** `delivery/me` via `flags.tsx` `useShareFlags` and `useFlag`. The `can()` helper supports `requires.flag` on pages too, but no page uses it.

## 7. Notes for the reshape

- Several apps share one URL across audiences: `marketing`, `people`, `deals`, `learn`, `notes`, `sites`, `calendar`, `marketplace`. `pageOf()` in `router.tsx` takes the first module with a matching id, which is the client variant when there is one. Moving a page needs the matching edit in both variants.
- `reactivation` embeds the engagement kit (`ENGAGEMENT_PAGES`: plan, updates, needs-you, paperwork, deliverables, results, contract, welcome) and `work` reuses it. Parking `reactivation` also parks those routes under `/reactivation/*`.
- `marketing/index.ts` does the "Today / Studio / Pieces / Numbers / More" collapse in `mainPlusMore()`. It already hides about 30 pages behind More or `lights`. The area-to-app map to change is `AREAS` in `areas.ts`.
- Some page ids are duplicated inside one module. For example team `marketing` declares `keywords`, `reports` and `ads` twice, and the first declaration wins.
- Wren's team-only Marketing area (`outreach`, `ads`, `sites`, `learn`) appears for clients only if the component is installed.
