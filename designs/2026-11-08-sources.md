# Sources: one list of every link William sends (WA-1195)

## Goal

One list holds every source William sends: reels, videos, posts, blogs, repos, skills, papers. Weaver reads each one once and keeps what it found. `weaver recall` and the agents search all of it. A new link reaches the list from any chat, the CLI or the portal. The old links come in once by a backfill.

## What exists (11-08)

- Learn (`learn.items`, 573 rows) is slated for removal (designs/2026-11-04-portal-places.md). Only about 102 rows are William's own saves: 51 by `wren learn add`, 51 by hand. The other 471 came from creators Learn followed (one account alone gave 224).
- Other links William sent: 20 in `tasks/docs/*/tasklog.md` and `temp_notes.md`, and about 700 links to other sites in chat transcripts. Instagram 70, GitHub 42, LinkedIn 42, YouTube 27, X 15, TikTok 15, Reddit 11. Many are links to tools or docs, not sources: an agent sorts them.
- Weaver already opens a person's URLs (the `paste` source). It reads YouTube captions, pages, Reddit, HN, arXiv and LinkedIn. Every record carries `from` (human, ai, tool) and `by`.
- Folders (WA-1191) group items of any kind by `(kind, ref)`.

## Options

| | Where the list lives | For | Against |
|---|---|---|---|
| A | The Weaver ledger: a `saved` record per link (URL, note, who, when, from what chat). `weaver save`, `weaver saved`, `weaver read-saved` | One research memory: recall covers his sources and every run's findings. Git-backed private repo. No second store | The ledger is on the Mac: the portal page and new reads need it on. Engine work |
| B | A wren Postgres table `sources`; Weaver reads it through `paste` | Always on; backed up with prod; the portal reads it directly | Two stores: the list in Postgres, what was found in the ledger, joined by URL. Recall misses the list |
| C | Keep `learn.items`, renamed | No build | The table being removed, with 40 reader columns; the same split as B |

Priorities, in order: one source of truth (what he sent and what was found in one place); recall over everything; intake from anywhere; nothing lost.

**Recommendation: A.** B and C split the list from what was read. A link from a phone while the Mac sleeps still works. The chat's agent runs on the Mac, so the link waits in the chat until it runs.

## Shape (A)

- Record `saved`: `url`, `kind` (reel, video, post, page, repo, skill, paper), `note`, `from: human`, `by: william`, `via` (chat id, tasklog line, learn item id), `at`. One per URL. A second send adds a note, never a second row.
- `weaver save <url...> [--note] [--via]`, `weaver saved [--kind] [--unread]` (JSON), `weaver read-saved [--limit]`: opens each unread one through the right source, extracts findings, marks it read. Reels and TikToks: the video source's captions or audio. No frame reads (`youtubeSee`) unless asked.
- Portal: Research › Sources, a list with kind filters, from `weaver serve`, like History. A folder kind `source` (ref = the record's URL key) so sources sit in the same folders as runs, chats and subjects.
- Intake: the agents' skill says "a link he sends as a source → `weaver save`". The CLI too.

## Backfill

1. Harvest candidates: Learn rows he saved (102), tasklog and temp_notes links, his chat messages' links, and his new list. Write them as one file in the private tasks repo.
2. An agent sorts each candidate: source or tool link. It saves the sources with a why.
3. `weaver read-saved` in batches. Cost: about 300 sources. Text extract on Haiku is about 1¢ each, so about $3 to $5. Reels add audio transcripts. William approves the spend before the run.
