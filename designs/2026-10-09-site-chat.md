# Site chat, 2026-10-09

Gaps item 9, product audit "More channels". GHL has live chat in Conversations. Ours: a chat
bubble on any site, threads in the Inbox, replies from the Inbox's box.

## Answer first

- **One tag.** `<script src="https://<host>/o/__chat.js" async></script>` on any page. `<host>` is
  the owner's: a client's custom domain, or wrenautomation.com for Wren. The host names the owner,
  as forms do.
- **The bubble.** Bottom right. Open, it shows the thread and a box. The first message asks a name
  and an email or phone, optional. The visitor's thread key lives in their browser
  (`localStorage`), so the thread survives page loads. While open it checks for replies every 4
  seconds; closed, never.
- **Inbox.** Each thread is a row, `chat:<id>`, type Chat, with the person's other channels when
  their email or phone matches a lead. A reply from the box goes on the `chat` channel: it shows in
  the bubble next time it checks.
- **Gate.** Replies run `replyGate` under the part `sites.chat`: Wren's own send, a client's send
  once an admin turns its `sites.chat` sends on, and ask otherwise, like every other channel.
- **Abuse.** 2,000 characters a message, 30 messages an hour per thread, 5 new threads a day per
  visitor IP (kept hashed), 200 a day per owner, and the portal's 120 posts a minute per IP on
  every public path (`apps/portal/src/limit.ts`). Bots (Cloudflare's verdict, the same `isBot` as hops) get no thread.
