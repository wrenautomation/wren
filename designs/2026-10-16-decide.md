# Decide: one interface for every machine call

2026-10-16. Bead wa-7pn. William: "use jev for now ... track all of its answers, and all of my
historical decisions, and we can use that as sort of distill sources to teach laya / fine tune
it". "Human has priority and me rejecting or going against a jev decision is also useful signal."

## Decisions

- **One seam: `decide()` in `@wren/core/decide`.** A kind names its questions; `decide` asks a
  backend, logs the whole answer as a `decisions` row and returns it. Any classification plugs in
  by adding a kind. Same shape as Jev's `/v1/systemone`: a `state` and typed questions (`noul`,
  `choice`, `score`), answers with probabilities and confidence.
- **Backends behind one interface.** `jev` (TypeSafe, the official JS SDK `@typesafe-ai/sdk`,
  MIT, no dependencies), base URL and model configurable, so Laya (`laya-serve`, same shape) is
  `jev` with another URL: `WREN_DECIDE=laya:<model>` plus `WREN_DECIDE_URL`. `gateway[:model]`
  asks our LLM gateway for the same answers as JSON and turns them into the same shape. Default
  `jev`; when Jev fails (not a refused input), the gateway answers and the row says so.
  `WREN_DECIDE=off` turns every call off.
- **Every call has a time limit and no retry storm.** One HTTP call waits at most `LIMITS.http`
  (2 min, `restate/limits.ts`), the SDK tries twice at most (20 s each). A pass stops after 3
  failures or 5 minutes. A refused key (401/402/403) stops the pass.
- **Spend with usage.** Each row keeps input and output tokens and `cost_usd`. Jev: $0.042 per 1M
  input tokens, output free. Gateway: free keys, $0. A daily cap (default $1, setting
  `decide.dailyUsd`) holds the pass when reached. Money is William's call; the cap only stops.
- **Two tables, in every database.** `decisions`: one machine answer (kind, subject, state,
  questions, raw answers, label, probability, confidence, backend, model, tokens, cost, latency,
  mode at the time, error). `decision_calls`: one human call (kind, subject, his label, `keep`,
  source, by, the decision it answered, `agreed`, `override`). Append-only, a unique `ref` so a
  replay or backfill adds nothing twice. Not audited (logs already).
- **Human always wins.** Nothing a decision says changes what he sees as approved or sent. A call
  against a shown pick is an `override`: kept as signal.
- **Modes per kind: off, shadow, recommend, gate.** Setting `decide` (Wren's settings block),
  `{ kinds: { <kind>: { mode } } }`. Shadow logs only. Recommend shows a small chip. Gate filters.
  Both kinds start in recommend. No kind has a gate filter built yet, so `gate` is refused until
  a kind declares one; the agreement table says when one qualifies (95% over at least 200 of his
  calls). Promotion is William's yes.
- **Two kinds now.**
  - `comment_quality`: our drafted comment (`comment:`, `thread:`, `onpost:` items). One choice:
    send / edit / drop. His call: sent with no edit = send, sent after his or Claude's edit =
    edit, rejected or passed = drop. Agreement is on keep (send or edit) vs drop: what a gate
    would filter.
  - `learn_worth`: a scored Learn item in Wren's workspace (`learn:<id>`). One choice: worth /
    skip, against `WREN_FOCUS` (sent in the state, so the scorer and Jev read one list). His call: star, pin, add to an SOP or save = worth; archive with
    none of those = skip.
- **Scored by a loop, not inline.** `Decide/wren` passes every 10 minutes: the open comment
  drafts whose newest model draft has no decision yet, and Learn items scored in the last 3 days
  with none. So the Mac's reads and the worker's are both covered, and no draft or score step
  waits on an outside API. At most 40 subjects a pass.
- **His calls are written where they happen.** `recordDraft` (the one write path for draft
  steps) writes the comment call on a send by him or by Claude at his ask, and on his reject. A
  scheduler's send (`via: wren`) and a guard's reject are not his. One call per draft round: a
  replay or the backfill of the same round adds nothing. Learn's `mark`, `askSop` and `saveLink`
  write theirs. Each links the newest decision on that subject before it.
- **Backfill.** `wren decide backfill` labels history: comment drafts from `draft_events`, Learn
  items from their marks, saves and SOP adds. `--sample N --max-usd 2` asks Jev about up to N
  backfilled subjects for a first agreement number. Prod today: about 20 comment calls, about 65
  Learn calls. Small: the set grows from here.
- **Export.** `wren decide export` writes `wren.decision/1` JSONL: state, questions, the
  machine's answer, his call. No handles or names go into a state.
- **Agreement view.** `wren decide stats` and a Decisions table on the Agents page: per kind,
  mode, his calls, agreement %, overrides, decisions, tokens, $. Portal reads through
  `ConsolePortal.decisions`.
- **Chips.** To approve, Engage and the Inbox take a `pick` field (Send, Edit, Drop) from the
  newest decision on each row's item, only in recommend or gate. Learn cards and Today lines show
  a small Worth / Skip chip beside the score.

## Shape

| Table | Columns |
|---|---|
| `decisions` | `id`, `kind`, `subject`, `mode`, `backend`, `model`, `state`, `questions`, `answers`, `label`, `p` (keep), `confidence`, `input_tokens`, `output_tokens`, `cost_usd`, `latency_ms`, `error`, `ref` (unique), `at` |
| `decision_calls` | `id`, `kind`, `subject`, `label`, `keep`, `source`, `by`, `decision_id`, `agreed`, `override`, `ref` (unique), `at` |

Indexes: `(kind, subject, at)` on both, `(kind, at)` on decisions.
